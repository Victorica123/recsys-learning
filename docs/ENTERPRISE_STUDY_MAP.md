# 企业知识扩展：八股对照

本页针对企业知识种子扩展，保留权限、数据处理和应用接入的复习材料。
视频/内容推荐主线的复习入口见 [八股复习地图](INTERVIEW_STUDY_MAP.md)。
每块准备到能说清“概念是什么、项目怎么用、出错会怎样”，就有了项目面试的落点。

## 第一轮：按这个顺序准备

| 顺序 | 八股与实践重点 | 本项目可以用到的部分 |
|---|---|---|
| 1. 页面与接口 | HTTP/JSON、参数校验、加载/空结果/失败状态 | MovieLens 页面与 API 共用推理核心；企业页面与接口作为接入练习 |
| 2. 权限与业务数据 | 身份与授权、事务、幂等、索引 | 企业资料范围检查、文档版本和反馈回放 |
| 3. 知识检索 | BM25、文本与向量检索的区别、结果排序 | 企业侧已有 BM25 与混合排序；MovieLens 提供向量检索学习材料 |
| 4. 大模型应用接入 | 模型 API、结构化输出、RAG（检索资料后再生成回答）、流式响应与取消 | 可在现有企业平台补练；本企业模块尚未接入生成模型与流式接口 |
| 5. 稳定性与质量 | 异步/线程池、超时与重试、限流、日志、结果评测 | MovieLens 服务已有线程池、限流与监控；企业模块已有排序降级和离线评估 |

大模型调用还要能解释如何保护服务端密钥、限制输入和调用成本，以及检索资料不足时如何处理。
这些是 AI 应用接入需要补练的内容。双塔训练、DeepFM 和强化学习作为专项追问材料。

<details>
<summary>企业模块直接对应的六块基础八股</summary>

| 顺序与章节 | 复习时重点留意 | 项目里的典型问法 |
|---|---|---|
| 1. 权限控制 | 认证与授权、RBAC（角色权限）、多租户隔离 | 为什么不能直接相信前端传来的角色？ |
| 2. 数据库事务 | ACID、提交与回滚、主键、外键、联合索引 | 一批反馈写到一半失败，怎样避免只留下一半数据？ |
| 3. 幂等与重试 | 唯一编号、唯一约束、重复请求、并发冲突 | 同一条反馈发了两次，怎样只记录一次？ |
| 4. 文本检索与排序 | TF-IDF、BM25、召回与排序、冷启动 | 用户还没有历史行为，为什么也能推荐资料？ |
| 5. 推荐评价指标 | Precision、Recall、NDCG | 命中同一份资料，排第一和排第五有什么区别？ |
| 6. 实验与数据切分 | 训练/验证/测试、过拟合、数据泄漏、随机种子 | 为什么明天才发生的反馈不能用于今天的推荐？ |

第一轮的数据库实现是 SQLite。通用事务和索引知识可以联系 MySQL 复习，MySQL 的具体实现属于接入延伸。
身份由调用方提供可信结果；本企业排序组件负责权限检查，JWT 登录链路由既有企业平台接入。

</details>

## 每块准备到什么程度

<details>
<summary>1. 权限：讲清“你是谁”和“你能看什么”</summary>

认证确认身份，授权决定可以访问哪些资源。RBAC 是按角色分配权限。
本项目还检查公司、工作区、文档所有者和文档有效时间，角色相同也不意味着能跨公司访问。

可以这样答：先从服务端确认的身份出发，检查请求范围与文档权限，通过后才读取文本并排序。
如果直接信任前端传来的角色或公司编号，用户就可能伪造权限。

代码：[enterprise_recommendation.py](../src/enterprise_recommendation.py) 的 `Principal`、`can_access()` 和 `active_at()`。

</details>

<details>
<summary>2. 事务：讲清一批操作怎样一起成功或撤回</summary>

ACID 对应原子性、一致性、隔离性和持久性。先理解原子性：一批关联写入要么全部提交，要么全部撤回。
主键防止身份重复，外键约束请求、候选和反馈之间的关系，联合索引用于匹配常见查询条件。

可以这样答：导入一次请求及其反馈时使用事务。中途数据校验失败就回滚，避免出现有反馈却找不到对应推荐的记录。
进一步追问时，再解释索引字段顺序为什么要配合公司、工作区和请求编号的查询。

代码：[enterprise_feedback.py](../src/enterprise_feedback.py) 的建表语句和 `import_dataset()`。

</details>

<details>
<summary>3. 幂等：讲清成功后的重试为什么不能再算一次</summary>

幂等表示重复执行同一个操作，最终效果与执行一次相同。
例如反馈已经写入，但调用方没收到成功响应，于是重试。

可以这样答：用公司、工作区和事件编号定位记录。编号及内容相同则跳过，编号相同但内容不同则报冲突。
处理放在写事务中，并使用数据库唯一约束。只在应用里先查再插，在并发请求下可能发生竞态。

本实现用 SQLite 的 `BEGIN IMMEDIATE` 开始写事务，不能把它表述成分布式“恰好一次”处理。
代码：[enterprise_feedback.py](../src/enterprise_feedback.py) 的 `record_event()` 与 `_record_event()`。

</details>

<details>
<summary>4. 排序：讲清文本为什么能提供相关性信号</summary>

TF-IDF 关注一个词在文档中的重要程度。BM25 也基于词语匹配，并考虑词频收益递减和文档长度。
召回负责从资料库里找候选，排序负责决定候选的先后顺序。

可以这样答：即使用户没有行为历史，当前需求和文档本身也有文本，可以先用这些内容判断相关性。
项目使用 BM25，再参考新鲜度与历史热度。它不需要先训练一个用户向量模型。

当前企业评估比较的是固定候选池上的排序；向量召回在 MovieLens 路线中另有实现。
代码：[enterprise_recommendation.py](../src/enterprise_recommendation.py) 的 `bm25_scores()` 与 `KnowledgeRanker.recommend()`。

</details>

<details>
<summary>5. 指标：至少能手算查准率与召回率，解释排名的影响</summary>

Precision 看推荐结果中有多少相关项；Recall 看应该找到的相关项找回了多少；NDCG 同时考虑相关程度和所在位置。

练习：相关资料有 A、B，推荐前三项是 A、C、D。此时 Precision@3 为 1/3，Recall@3 为 1/2。
如果只把 A 从第一位移到第三位，前两项指标不变，NDCG 会下降。

可以这样答：方案比较必须使用相同请求、相同候选和同一套标签。
本企业报告的标签来自种子规则，分数描述这套数据上的表现。

代码：[enterprise_evaluation.py](../src/enterprise_evaluation.py) 的 `ranking_metrics()` 与 `evaluate_dataset()`。
偏算法岗再补 AUC 与 GAUC，并说明整体分类指标不等于前几条推荐的质量。

</details>

<details>
<summary>6. 数据切分：讲清当时到底能知道哪些信息</summary>

训练集用来学习，验证集帮助选方案，测试集用于最终评估。反复根据测试集改方案，也会让测试结果偏乐观。
数据泄漏是把预测时本不该知道的信息带入了训练或打分。

可以这样答：即使某次请求发生在训练期，它关联的行动完成也可能晚于训练截止时间。
计算历史热度时应看反馈真正发生的时间，不能只看请求被分到了哪一组。

固定随机种子方便复现；公平比较还要对齐请求、候选和评估方法。
代码：[enterprise_evaluation.py](../src/enterprise_evaluation.py) 的 `history_popularity()`。

</details>

## 第二轮：按岗位要求或简历中的技术继续展开

| 方向 | 优先补的八股 | 用本项目练哪道题 |
|---|---|---|
| 推荐算法 | Embedding 与双塔、负采样；FM/DeepFM 特征交叉；之后再看 Transformer/SASRec | 为什么训练分数不错，接入整条推荐链路却可能变差？ |
| AI 全栈应用的工程追问 | 索引与查询；线程/进程/异步；令牌桶限流、过载保护、p95/p99 | 为什么阻塞操作放在线程池？增加 worker 为什么会增加内存？ |
| 强化学习专项 | 状态/动作/奖励、探索与利用、DQN 与策略梯度 | 为什么学习策略可能输给简单规则，怎样设计公平对照？ |

当前先把应用流程与工程问题讲熟。岗位明确要求推荐建模时，再深入双塔和负采样；
更复杂的强化学习方法按岗位要求或自己简历中写到的内容继续展开。

对应代码：算法看 [train_two_tower.py](../src/train_two_tower.py)、
[train_deepfm.py](../src/train_deepfm.py) 与 [train_sasrec.py](../src/train_sasrec.py)；
服务看 [serve.py](../serve.py) 与 [observability.py](../src/observability.py)；
RL 看 [train_dqn_rec.py](../src/train_dqn_rec.py) 与 [train_pg_rec.py](../src/train_pg_rec.py)。
具体实验故事和追问见 [进阶面试资料](INTERVIEW_DEEP_DIVE.md)。
