# 视频 / 内容推荐：AI 全栈面试手册

主线是“用户偏好 → 内容推荐 → 页面/API → 曝光反馈 → 评估改进”。先讲业务流程，再按追问展开算法。

## 60 秒介绍

> 我做了一个面向视频和内容分发的推荐原型，当前用 MovieLens 电影评分数据验证。
> 系统根据用户画像和历史偏好，通过双塔模型与向量检索返回相关内容，并提供网页 Demo 和 HTTP API。
> 工程上，网页调用推荐 API，在同一页面记录曝光和用户选择；反馈失败后沿用事件编号重试，数据库保证不会重复计数。
> 我还做了服务限流、监控和端到端评估。一个具体发现是，加入精排后整体效果反而下降，所以经过对照验证后，默认保留双塔直接推荐。

## 三个重点

**推荐功能怎样工作。** 用户和内容分别编码成向量，通过相似程度检索候选，过滤已经评分的内容，再返回 Top-K。

**怎样交付成应用。** 页面负责交互，API 负责校验和调度，推荐核心负责推理。反馈带上推荐批次和版本，便于追踪和比较；容器提供统一启动方式。

**怎样保证改动有价值。** 对照基线看整体推荐结果，同时检查延迟、错误和反馈记录。更复杂的模型需要通过评估再采用。

## 五个常见追问

**这是完整的“搜索、广告、推荐”系统吗？**

当前完成的是内容推荐及其服务、反馈和评估。搜索需要面向查询词的相关性处理，广告还需要出价、预算、点击与转化等数据和目标。
这些可以继续扩展，现有 MovieLens 评分不能直接当作广告点击或转化标签。

**双塔和 Faiss 各做什么？**

双塔学习用户与内容的表示，Faiss 根据向量找到相似内容。当前使用精确内积检索；大规模近似索引可以作为进一步学习内容。

**为什么没有把 DeepFM 精排作为默认？**

单独模型的评分不错，不代表接入整条链路就更好。端到端实验发现它让结果过度集中在热门内容，整体推荐效果下降。
多轮修复仍未证明稳定增益，因此默认服务采用双塔 Top-K。

**前端、后端和反馈怎样组织？**

主网页 `web/index.html` 调用 Starlette 的 v1 API，再进入 `src/serving.py`。
页面记录进入视口的推荐项，点击前确保曝光已保存；同一事件重试只写入一次，冲突内容返回 400。
原 Streamlit 展示与反馈实验台保留为独立入口，直接调用 Python 核心。

**怎样把它用到短视频场景？**

复用推荐服务、反馈记录和评估思路，按视频业务重新设计用户、内容和行为字段。
重点补曝光、播放时长、完播、跳过等信号，再确定推荐目标。可以先生成符合这些规则的模拟数据来演练。
已有企业知识种子属于另一条扩展，不能改个名字就当作视频播放日志。

## 八股重点

AI 全栈应用岗优先准备：页面/API、向量检索、数据库事务与幂等、异步与限流、推荐指标和数据切分。
对应 [八股复习地图](INTERVIEW_STUDY_MAP.md)。双塔训练、精排和序列模型按岗位要求深入；强化学习放在专项追问中。

## 面试前最后五分钟

1. 打开 Demo，完成“用户 1 → 推荐 → 感兴趣”，解释数据怎样保存。
2. 讲清页面、推荐核心、API 和反馈记录的关系。
3. 准备一个能深入解释的案例：精排效果下降、重复反馈处理或服务过载保护。复现命令与实测见 [交付验证](APPLICATION_DELIVERY.md)。

开发使用了 AI 辅助，个人贡献结合自己能解释、修改和验证的代码来讲。
运行入口见 [项目导学](../项目导学.md)，完整研究问题见 [进阶面试资料](INTERVIEW_DEEP_DIVE.md)。
