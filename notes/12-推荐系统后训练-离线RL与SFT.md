# 12 · 推荐系统"后训练"：离线 RL + SFT 微调

> 阶段目标：把大厂 LLM 的**后训练范式**（预训练 → SFT → RLHF）搬到推荐系统，
> 并落在真实业务约束上——**线上不能自由探索，只能用固定日志离线训练**。
> 代码见 `research_v2/phase2_offline_rl/`，本篇讲清楚做法、原理、推理和**诚实的结论**。

---

## 一、为什么推荐的"后训练"必须是离线的

LLM 后训练三段式：**预训练**（学语言）→ **SFT**（模仿好答案）→ **RLHF**（按奖励做策略提升）。
推荐系统的对应物：

| LLM | 推荐系统本项目 |
|-----|----------------|
| 预训练 | SASRec 序列建模（学"用户下一步想看什么"）——见 notes/08 |
| SFT | **行为克隆**：监督式模仿日志里"实际推了哪个物品" |
| RLHF / RL | **离线 RL**：在固定日志上做策略提升，优化长期满意度 |

**核心约束**：线上推荐系统每天服务千万用户，你**不能**为了试验让它随机乱推（会直接损失营收、伤害体验）。
你手里只有**行为策略**（当前线上模型）产生的**历史日志**。因此推荐的策略优化天然是
**离线（offline / batch）RL**：从固定数据学习，训练期间一次都不碰环境。这正是本阶段区别于
notes/09（在线 DQN 边交互边学）的根本点。

---

## 二、流水线与三个阶段的原理

```
行为策略(ε-greedy 短视) ──滚动──▶ 固定日志(离线数据集, 含 return-to-go)
                                        │
                    ┌───────────────────┼───────────────────┐
                    ▼                   ▼                   ▼
              SFT 行为克隆         奖励加权 BC          离线 RL(CQL / naive)
                    └───────────────────┴───────────────────┘
                                        ▼
                     RecSimEnv 评估(仿真器充当"在线 A/B 预言机")
```

### 2.1 采日志：把"生产日志"固化成固定数据（`dataset.py`）

- **行为策略**：ε-greedy 的短视贪心——ε 概率随机探索，否则选**即时** SASRec 打分最高的物品。
  它"还不错但短视"：会连续推同类型直到用户疲劳退出，恰好给离线 RL 留下提升空间。
- 记录五元组 `(s, a, r, s', done)`，并从会话末尾往前回填**折扣 return-to-go**
  `Gₜ = rₜ + γ·rₜ₊₁ + γ²·rₜ₊₂ + …`（给奖励加权 SFT 用）。
- 数据一旦落盘（`*_dataset.npz`）就**冻结**，后续 SFT/RL 全程只读它——这就是"离线"的工程含义。

### 2.2 SFT：行为克隆（`behavior_cloning.py`）

- **普通 BC**：状态 → 动作的交叉熵分类，`L = CE(π(s), a_logged)`。**只模仿，不看奖励**。
  它复刻行为策略的一切——包括它的短视。
- **奖励加权 BC（RWR / filtered BC）**：给每条样本按 return-to-go 加权
  `w = softmax(G/τ)`，只重点模仿"高长期回报"的示范。**这正是 LLM 里"拒绝采样 SFT /
  best-of-N"的思路**——是从纯 SFT 迈向 RL 的第一步（有了策略提升的味道，但仍不需要 Bellman 自举）。
- **原理·SFT 的天花板**：BC 的目标是"复现示范分布"，所以它的性能**上界就是行为策略本身**，
  永远学不出比数据更好的策略。这和"LLM 的 SFT 无法超过示范者水平"是同一件事。

### 2.3 离线 RL：保守 Q 学习 CQL（`cql.py`）

- 离线 RL 想**超过**行为策略，就得用 Bellman 做策略提升：`y = r + γ·maxₐ' Q(s',a')`。
- **致命问题·外推误差（extrapolation error）**：那个 `maxₐ'` 会挑中数据里**没出现过的
  OOD 动作**，而 OOD 动作的 Q 纯属网络瞎猜、还被 max 系统性选成"看起来最高"的；
  自举把高估一轮轮放大 → Q 爆炸、策略崩。在线 DQN 能靠真实交互纠偏，**离线没有这个机会**。
- **CQL 的解法**：给 TD 损失加保守正则（离散动作版 CQL(H)）：
  ```
  L = L_TD + α · E_s[ logsumexp_a Q(s,a) − Q(s, a_data) ]
                       └──── 压低所有动作 ────┘ └ 抬高数据内动作 ┘
  ```
  第一项把"所有动作"（尤其被 max 挑中的 OOD 动作）的 Q 压下去，第二项把"数据里真实出现过
  的动作"的 Q 抬上来 → 学到的 Q 对没见过的动作**保守**。`α=0` 时退化为 naive 离线 DQN。

## 三、实验与**诚实的结论**（ML-1M，RecSimEnv，200 会话评估）

> ⚠️ 仿真器（冻结 SASRec 用户模型 + 手工疲劳/厌倦动力学）在这里充当我们现实中拿不到的
> "在线 A/B 预言机"。指标是这个仿真器下的研究证据，不是线上产品保证。

### 3.1 SFT 忠实复刻行为策略，且**无法超越它**

用**确定性贪心**日志（ε=0）做 BC，模仿保真度 **99.71%**，最终 reward **2.87** ——
和短视贪心行为策略**分毫不差**。奖励加权 BC 同为 2.87。**SFT 的天花板 = 数据策略**，实验完美印证。

### 3.2 离线 RL（Bellman）**突破** SFT，学出交错策略——后训练的价值

| 日志(行为策略) | SFT 行为克隆 | **naive 离线 DQN** | 随机(交错基线) |
|---|---|---|---|
| 5.14（ε=0.2）| 2.92 | **9.34**（多样性 4.89）| 6.88 |
| 2.64（ε=0）| 2.87 | **8.03** | 6.88 |
| 3.85（12 动作）| 2.83 | **13.59**（best）| 6.88 |

- 从一个短视、低多样性（≈1.0）的行为策略日志出发，**离线 Bellman 学习恢复出了高多样性
  （4.4~4.9）的交错推荐策略，reward 提升 2~4 倍**，甚至超过随机基线。
- 这就是"**RL 后训练 > SFT**"的推荐版：SFT 停在数据策略（2.87），RL 越过它（9~13）。
  背后是 notes/09 的核心洞见——**含疲劳动力学时最优策略必须交错类型**，Bellman 能发现这点，模仿学不到。

### 3.3 CQL 的保守是**双刃剑**：α 权衡曲线（同一数据集消融）

| α | 0（naive）| 0.5 | 1 | 2 | 5 |
|---|---|---|---|---|---|
| reward | **10.75** | 4.45 | 4.11 | 3.39 | 3.10 |
| 多样性 | 5.50 | 1.55 | 1.39 | 1.20 | 1.08 |
| 训练末 Q 均值 | 8.95 | −2.00 | −2.42 | −2.20 | −2.25 |

- **单调**：α 越大 → 越保守 → 策略被拉回（短视的）行为分布 → 多样性掉到 ≈1.0、reward 掉到贪心水平。
- **推理**：保守项在每个状态抬高"数据里真实出现的动作"的 Q。而日志由**短视**策略产生，
  数据动作大多是短视的，于是 CQL 反而**强化了短视** → 越保守越像贪心。

### 3.4 为什么这个环境里 naive DQN 反而最稳？（关键工程判断）

教科书里 CQL 通常 > naive，本项目却相反。**诚实归因**：
1. **回报有界**：会话因"厌倦"最多 20 步就退出，加上 QNet 的 LayerNorm，Q 值天然被夹住，
   不会出现经典的 Q 爆炸。即便把日志窄化到**只有 12/200 个动作**，naive DQN 也没发散（reward 13.59）。
2. **动作全部合法**：这里 200 个动作都是**真实、可执行**的物品，"OOD 动作"依然有良态的真实
   反馈动力学；而经典 CQL 发散场景里 OOD 动作往往是不可执行的垃圾外推。
3. 因此**驱动 CQL 存在的"外推误差灾难"在这个推荐 MDP 里不成立**，保守只带来净损失。
- CQL 机制本身是对的（`tests/test_offline_rl.py::test_cql_suppresses_out_of_distribution_action_values`
  在受控合成数据上验证了"OOD 动作 Q 被压低"）——**它只是不适配这个具体环境**。

> **工程结论**：离线 RL 落地的第一课不是"用哪个 SOTA 算法"，而是**判断你的数据覆盖与回报结构
> 是否真的需要保守**。覆盖足够、回报有界时，简单的离线 Double-DQN 已足够且更强；覆盖窄、
> 动作含不可执行外推时，才用 CQL/BCQ/IQL 这类保守/受限方法。**先诊断，再选药。**

---

### 3.5 文献驱动的对照：IQL 也逃不出行为策略（2026-08-05 新增）

受文献库启发（IQL, arXiv:2110.06169；离线 RL 实现指南, arXiv:2306.00972），
按「保守不行就换免 max 的路线」做了 IQL 对照：它不对未见动作做 max，用
expectile 回归的 V(s') 替代 Bellman 目标里的 max Q，理论上不需要保守项就能
避开 OOD 高估。实现：`research_v2/phase2_offline_rl/iql.py`
（Q + expectile V + 优势加权 BC 三件套）。

同一份 phase2 日志、15000 步、300 会话同协议评估：

| 方法 | reward | 长度 | 多样性 |
|---|---:|---:|---:|
| SFT 行为克隆 | 2.89 | 7.8 | 1.01 |
| CQL 离线 RL（α=1） | 3.63 | 8.8 | 1.38 |
| IQL 离线 RL（τ=0.7, β=3） | 3.35 | 8.3 | 1.20 |
| IQL（τ=0.5, β=1，更激进） | 3.40 | 8.3 | 1.20 |
| **naive 离线 DQN** | **9.43** | 15.6 | 4.83 |

**结论**：IQL 与 CQL 站在同一边——都被拉回行为策略附近（3.3~3.6），naive 的
max 自举外推依然是唯一能发现交错策略的机制。两个 τ/β 组合结果一致，排除超参
偶然。3.4 的工程结论因此被强化并细化：

- 驱动离线 RL「安全机制」的 OOD 高估灾难，在这个推荐 MDP 里确实不出现；
- 而「危险」的 max 外推，在这里恰恰是策略提升的来源——数据里从未出现的交错
  动作被 naive DQN 的 max 挑中并验证是好的；
- 所以本环境的正确解法不是换一个保守/受限算法（CQL→IQL 都无效），而是
  保证数据覆盖 + 直接做 Bellman 外推；要展示 CQL/IQL 的价值，必须先造出
  「naive 会发散」的场景（不可执行动作 / 更强非平稳）。

复现：`.venv/Scripts/python.exe research_v2/phase2_offline_rl/train_iql.py
--steps 15000`；测试：`tests/test_iql.py`（5 用例：AWR 权重性质 + IQL 更新统计）。

## 四、工程落地要点

- **数据与训练解耦**：日志固化成 `*.npz`，SFT/RL 全程只读——可复现、可审计、可复用（α 消融直接复用同一份数据，不重采）。
- **对照可控**：CQL 与 naive 吃**完全相同**的 batch 序列，唯一变量是 α；各策略评估用**同种子同会话流**，消除评估噪声。
- **可测试**：`tests/test_offline_rl.py`（8 用例）+ `tests/test_iql.py`（5 用例），
  合成数据、CPU、无仿真器，锁死 return-to-go、BC 模仿保真、CQL 保守性、AWR 权重
  四条不变量；纳入 `--test` 冒烟套件。
- **可复现**：沿用 `config.set_seed` + `ExperimentConfig`，每次运行落 `*_config.json`。
