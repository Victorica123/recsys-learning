# 前沿 RL 论文调研与落地路线（2026-08-05 扩充至 50 篇）

> 目的：把 RL 领域高引用、近年前沿的论文映射到本项目已有资产上，挑出
> **有落地可能**的方向并实际做掉第一个（手写 PPO）。
> 背景：项目已有手写 DQN / REINFORCE+Actor-Critic / 离线 RL（BC、naive DQN、
> CQL）/ Agentic 工具门控 / 真实反馈闭环——这些恰好是"推荐 × RL"路线图的
> 基础件，前沿方法都能在它们上面加一层。

## 一、筛选标准（与初版一致，严格执行）

1. **主题相关**：属于"策略优化 / 偏好对齐 / 离线决策 / 推荐×RL / 探索 /
   Bandit / 模仿学习"其中至少一类；
2. **影响力**：经典论文引用量级在千级及以上；2024–2025 新作选同主题里已被
   后续工作验证、或在工业界有落地先例的；
3. **出处可验证**：每条给出 arXiv 编号或会议/期刊出处（逐一核对，初版中的
   错误编号已修正）；
4. **可落地**：在本项目资产（RecSimEnv、离线 npz 数据集、反馈闭环、Agentic
   门控、双塔/DeepFM/SASRec）上至少有一个明确的结合点。

影响力列为**量级估计**（截至 2026-08，Google Scholar / Semantic Scholar 数量级，
非精确引用数）：极高=万级+，高=千级，中高=百~千级，新兴=百级且上升很快。

## 三、被严格筛掉的候选（说明标准执行）

- **DDPG**：连续控制专用，已被 SAC/TD3 覆盖；本项目动作是离散 Top-200。
- **A3C**：核心贡献是异步并行；项目是单进程训练，实质已被 PPO 涵盖。
- **HER**：目标条件 RL，本项目会话无显式目标设定，结合点弱。
- **MuZero / MBPO / TD-MPC**：基于模型的树搜索/连续控制方法，偏棋盘与机器人，
  与推荐会话决策的落点弱（Dreamer 家族已代表世界模型方向）。
- **Diffuser（轨迹扩散规划，arXiv:2205.09991）**：生成式规划，工程重、落地远。
- **Phasic Policy Gradient**：影响力有限，无独立方法论增量。
- **VAPO (arXiv:2504.05118)**：面向长 CoT 的值函数型 PPO，与 GRPO/DAPO 重叠且引用尚少，留待 GRPO 阶段之后再看。
- **Constitutional AI / RLAIF**：对齐重要但与 RL 算法主线距离远，且与本项目结合弱。
- **ReBRAC**：与"离线 RL 实现指南"重复，保留指南即可。
- **GFlowNets（生成式流网络）**：生成式策略前沿，但推荐场景尚未成主流，暂缓。
- **TALLRec / PALR 等 LLM 推荐微调**：无 RL 核心，已由 LLM4Rec 综述覆盖。
- **RecSim NG / 平台类延伸**：平台工具而非方法，保留 RecSim 本体即可。

## 五、推荐路线（三阶段）

### Phase A：手写 PPO for RecSimEnv —— 已完成（2026-08-05）

**协议**：与 `train_pg_rec.py` / `train_dqn_rec.py` 完全同台——同一冻结 SASRec
用户模型、同一 `RecSimEnv`（疲劳 + 流失）、相同种子（seed 42）、相同 300 会话
评估流。网络复用 PG 的 ActorCritic（83 维状态 → 200 动作）。PPO 独有：GAE(λ=0.95)
优势、clip ε=0.2、K=4 轮复用、优势标准化。

**结果**（300 会话，同种子公平对比）：

| 策略 | 平均奖励 | 会话长度 | 类型多样性 |
|---:|---:|---:|---:|
| 随机 | 6.69 | 13.2 | 4.78 |
| 贪心（短视） | 2.81 | 7.7 | 1.00 |
| Double DQN | 7.63 | 13.7 | 4.08 |
| 策略梯度(argmax) | 5.07 | 10.5 | 1.76 |
| 策略梯度(采样) | 15.86 | 19.5 | 5.42 |
| **PPO(argmax)** | 4.11 | 9.8 | 1.74 |
| **PPO(采样)** | **15.43** | 19.2 | **6.87** |

**诚实结论**：
1. PPO(采样) 与 PG(采样) 奖励基本持平（15.43 vs 15.86，−2.7%），但类型多样性
   高 26.8%（6.87 vs 5.42）——clip + 熵正则让策略保留更多探索。
2. argmax 依然塌缩（2.68→4.11），与 PG/Agentic 的既有结论一致：**这个仿真器
   必须采样部署，argmax 不是等价部署**。
3. 本仿真器小而简单，PG 单步更新已接近最优；PPO 的 clip/复用优势在更难的
   设定（大规模候选、稀疏奖励）才显著——这正是 GRPO/Rank-GRPO 要上场的地方。

**复现**：`.venv/Scripts/python.exe src/train_ppo_rec.py --updates 40 --resume`
（或 `--updates 1 --no_eval` 冒烟）；`tests/test_ppo_rec.py` 锁死 GAE 三条不变量。

### Phase B：GRPO for Agentic 工具门控 —— 已完成（2026-08-05）

- `research_v3/agentic_rec/train.py` 新增 `--algo grpo`（旧策略比裁剪 ε=0.2 +
  KL 正则 β=0.04 + `--epochs K` 多轮复用），参考策略 = 训练起始冻结快照
  （论文里是 SFT 模型，本项目门控无 SFT 版本，已在笔记中注明）。
- 结果（同配置 300 会话）：GRPO K=4 采样净奖励 16.668 vs REINFORCE 15.905
  （+4.8%），工具调用率 70.4% → 85.8%；K=1 的 GRPO ≈ REINFORCE（KL 单独无效）；
  argmax 仍塌缩，规则门仍是最优部署（17.423 vs 16.668）。
- 实现教训：第一版"在线参考 + 单步更新"的 GRPO 逐位退化成 REINFORCE
  （ratio=1、KL 梯度为零），修正为冻结参考 + 多轮复用后裁剪/KL 才生效——
  这解释了论文为什么要冻结参考模型。详见 notes/13。
- 复现：`train.py --algo grpo --epochs 4 --tag <new-tag>`；
  测试：`tests/test_agentic_rec.py`（14 用例，含 5 个 GRPO 损失用例）。

### Phase C：DPO/S-DPO 重排 on 反馈闭环（落地可能最强）

- 现状：`feedback_app.py` + `src/feedback.py` 已采真实 click/skip 偏好对，
  OPE（IPS/SNIPS + bootstrap + ESS）门槛现成。
- 做法：把"点了 A 没点 B"的 (chosen, rejected) 对喂给 DeepFM 重排器的
  DPO/S-DPO 损失（先仿真器/离线偏好开发，真实样本够门槛再出正式结论）。
- 与现有流程的关系：DPO 训练出的重排策略 = 新的 candidate policy，仍走
  `compare_logged_policies` 的 promote/keep/continue 决策门槛——闭环自洽。

## 七、给初学者的三句话

- **PPO** = 每步只改一点点（clip）+ 旧数据多用几轮（重要性比）+ 少一点方差
  （GAE）。是当前 RL 的工业主力。
- **GRPO** = PPO 去掉价值网络，用"同一批候选互相比较"代替它——这就是
  DeepSeekMath/R1 训练 ChatGPT 类模型的同一套方法。
- **DPO** = 连在线采样都不需要，直接拿偏好对训练——对推荐最友好，因为推荐
  系统本来就有海量隐式偏好（点击/跳过）。

## 八、诚实边界

- 仿真器（冻结 SASRec + 手写疲劳/流失奖励）的结果是**研究证据，不是线上保证**。
- PPO 与 PG 的对比中，PG 数字取自历史 `pg_eval.csv` 基线，PPO 用了约两倍训练量
  （80×32 回合）——差异以"量级相同、多样性更高"表述，不做谁碾压谁的结论。
- 影响力列为量级估计而非精确引用数；REINFORCE（期刊 1992）与 DRN（WWW 2018）
  无 arXiv 编号，已注明出处；2025 年新论文引用量仍在增长。
