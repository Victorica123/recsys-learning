# 从 MovieLens 到企业知识：先验证数据与决策链路

来源是用户网页端《网页端能力对比》对话，以及 2026-09-13 生成的
`enterprise-recsys-synthetic-pilot.zip`。本次按其中“先接入 recsys-learning 验证排序与反馈，
再接企业平台”的顺序，完成当前仓库的离线侧实现。

## 1. 建议如何落地

建议最有价值的转向是给推荐系统一个具体上下文：
用户看完一次会议分析或 PRD，需要找到当前工作区内相关、已批准且仍有效的历史知识。
有效业务结果包括引用知识、创建行动项和完成行动项，而不只是点击。

本轮选择：

- 复用评估与反馈方法，为企业物品建立独立的数据契约。
- 先建立时间/热度、文本相关性和混合排序基线。
- 将排序函数与版本化策略交付给既有 Agent Service。
- 显式保留“合成验证”和“真实业务收益”之间的证据边界。

MovieLens 数据和权重不迁移到企业业务。新增模型、RL 或第三个后端无法解决当前真实反馈不足的问题。

## 2. 原种子包的价值与问题

原包提供 4 个虚构租户、40 个用户、136 份文档、104 条文档关系、640 次推荐请求，
以及 5,870 条曝光和行为事件。它适合用来验证授权、版本、幂等、排序与反馈契约。
本仓库保留其文案和随机规则，默认种子 `20260913` 生成的全部 JSONL 哈希与原包一致。

原包的数据检查和评估脚本可以运行，但不能直接把 0.2799 与 0.9668 当作策略提升：

| 审计发现 | 对结论的影响 | 本轮处理 |
|---|---|---|
| 两个策略各有 20 个用户，共同用户数为 0 | 用户差异和策略效应混杂 | 每条请求分别运行全部三种策略 |
| 策略先从授权目录筛出 Top-16，再保存候选 | 保存的是曝光策略的候选池，不是全授权目录 | 三种策略只比较同一有标签候选池，明确条件性范围 |
| `topic_match` 与真值等级共享同一主题关系表 | 高分部分来自合成规则自身 | 新排序器只用文本、角色、时间和过去行为 |
| 80% 请求的 epsilon 为 0 | 未展示项目的概率为零，无法任意重加权 | 输出支持度审计，拒绝声称 OPE 业务增益 |
| 一个训练请求的行动完成发生在训练截止后 | 仅按 split 标签聚合会产生未来信息 | 使用实际 occurred_at 和训练截止双重过滤 |
| 原生成器会删除输出目录 | 重跑可能丢失已保存的数据 | 改为显式输出目录并拒绝覆盖 |

原始候选池平均只占当时授权目录的 **53.7%**。本轮的 Recall@5 是在这批候选中的
标签覆盖率，不是全目录召回率。

## 3. 正确的时间与特征边界

原协议以 `2026-01-01T09:00:00Z` 为起点：

- train：第 0 至 59 天；实际请求从第 30 天开始。
- validation：第 60 至 74 天。
- test：第 75 至 89 天。

对应请求数为 325 / 163 / 152。请求、候选和标签保持同组。
行为保留真实发生时间，可能晚于所属请求的窗口。

训练期请求只读取该请求之前到达的训练事件；
验证与测试都只读取训练截止之前到达的训练事件。
热度特征按打开、引用、收藏和行动项事件构建，并按请求/物品/事件类型去重。
训练以后的事件即使标记为 train，也不能进入冻结特征。

文档权限先于文本处理。旧版本在替代前可用，边界开始不可用；新版本在创建前不可用。
未来文档和无权限文档不会影响 BM25 的词频、IDF 或归一化统计。
种子中的成员资格是静态的，无法验证真实组织中角色授予、撤回的历史变化。

## 4. 实际结果

新策略共享每条请求的相同 16 项有标签候选，参数在评估前固定。
`semantic_v1` 使用 BM25，命名沿用网页建议，但它不是神经语义向量模型。
所有结果都属于固定模板与合成标签的工程验证。

| 测试策略 | 请求数 | NDCG@5 | MRR@5 | Recall@5 |
|---|---:|---:|---:|---:|
| baseline_v0：时间＋训练期热度 | 152 | 0.2959 | 0.4959 | 0.2940 |
| semantic_v1：文本相关性 | 152 | 0.8875 | 0.9803 | 0.6623 |
| hybrid_v1：文本＋业务先验＋多样性 | 152 | 0.8949 | 0.9789 | 0.7207 |

混合策略在本合成测试上的 NDCG 比文本基线高约 0.0074，但这不是现实业务效果，
也没有做“显著提升”的推断。文本模板和合成真值仍有很强的词汇关联；
应以此证明管道和对照可运行，不能把数字搬进简历声称客户收益。

按现有行为日志，三种新策略的 3,200 个目标展示位置中，分别有
1,396 / 1,186 / 1,133 个在对应行为策略下的倾向概率为零。
因此没有计算假想的新策略打开率、引用率或 IPS 增益。

通用反馈导入保存了 640 个请求、10,240 个候选与 5,870 个事件；
重复导入新增请求和事件均为零。源事件按原政策和模型分组描述，
观察截止之后的一条行动完成事件保留在回放中，但不计入截止前业务指标。

## 5. 当前决策

机器可读结果始终是：

```json
{
  "status": "not_promoted_synthetic_only",
  "train_two_tower": false,
  "real_business_lift": null
}
```

本轮完成合成种子接入、授权排序、反馈契约和可复现实验。企业平台线上集成与真实用户试点尚未完成。
下一步应在现有分析/PRD 页面展示相关知识，让参与者实际打开、引用、驳回或创建行动项，
再按用户、时间、策略版本和数据支持度决定保留基线、继续收集或尝试模型训练。

面试可表述为：

> 将 MovieLens 项目的评估与反馈方法扩展到企业知识推荐的离线侧，建立多租户授权候选、
> 文档版本、幂等曝光与业务事件回放；审计合成种子的用户分组混杂、候选截断和未来反馈，
> 在同请求同候选池下比较三条基线，交付可嵌入 Agent Service 的排序函数。
> 当前是合成数据验证，没有声称真实业务提升。
