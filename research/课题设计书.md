# 课题设计书（Phase 2 · 研究版）

# 从序列推荐到强化学习推荐：面向长期用户满意度的推荐策略研究

> 一份"研究生式"课题方案：有论文依据、有实验矩阵、有基线复现、有消融实验、
> 有研究创新点。预计周期 3~5 周，实验总机时数十小时（可分段时间跑）。

---

## 一、研究背景与问题

Phase 1 我们验证了推荐系统的经典流水线（双塔召回 + DeepFM 排序 +
Bandit 探索），但有两个根本性缺陷，恰好是近十年推荐系统研究的两条主线：

1. **静态视角**：DeepFM/双塔把每个 (用户, 物品) 对当成独立样本，
   丢掉了"用户刚才看了什么"的序列信息。同一用户看完《教父》后和
   看完《海绵宝宝》后，该推的东西完全不同。
   → 主线一：**序列推荐**（GRU4Rec → SASRec → BERT4Rec）

2. **短视决策**：CTR 预估和 Bandit 都只在优化"这一次点不点"，
   但平台真正要的是长期留存（用户这个月还来不来）。为一次点击
   牺牲多样性，用户会流失 —— 这是多步决策问题。
   → 主线二：**强化学习推荐**（MDP 建模 → DQN 系方法）

## 三、研究内容与技术路线

### 模块 1：序列推荐论文复现（约 1.5 周）
- 实现 **SASRec**（Transformer 单向因果注意力，论文[2]），严格按论文协议：
  leave-one-out（最后 1 个测试 / 倒数第 2 个验证）、100 个负采样、HR@10 / NDCG@10
- 复现目标：ML-1M 上 HR@10 ≈ 0.82、NDCG@10 ≈ 0.59（论文报告值）
- **数据集升级**：ML-1M（100 万）→ **ML-25M（2500 万评分）**，验证可扩展性
- **消融实验矩阵**（论文必备环节）：
  | 变量 | 取值 |
  |------|------|
  | Embedding 维度 d | 64 / 128 |
  | Transformer 层数 | 1 / 2 / 3 |
  | 最大序列长度 | 50 / 200 |
  | dropout | 0.2 / 0.5 |
- 产出：复现结果表 + 消融曲线 + 与 Phase 1 模型的协议差异分析

### 模块 2：RL 推荐研究实验（约 2 周）★ 创新点所在
- 把推荐建模成 **MDP**：状态 = 用户最近 N 次交互序列（用模块 1 的
  SASRec 编码成状态向量）；动作 = 推荐哪部电影；奖励 = 用户反馈
  （喜欢 +1 / 无感 -0.1 / 会话结束），γ = 0.9 折扣长期收益
- 环境：用真实数据 + 模块 1 训练的用户偏好模型搭建**离线仿真器**
  （这是论文 [4][5] 的标准做法，也是工业界离线 RL 的入门姿势）
- 方法对比实验：
  | 方法 | 类型 | 对应论文 |
  |------|------|----------|
  | 贪心（SASRec 直接推最高分） | 基线（短视） | [2] |
  | LinUCB | 单步 Bandit | Phase 1 |
  | **DQN（手写实现，不用现成库）** | 多步 RL | [7] |
  | DQN + 探索增强 | 改进 | [4] |
- 对比指标：单回合平均奖励、**会话累积折扣奖励（长期收益）**、推荐多样性
- 产出：证明"多步 RL 在长期收益上优于贪心/单步 Bandit"的实验证据链

## 六、风险与对策

- **ML-25M 训练慢**：序列模型可按用户子采样做开发集，全量只跑最终实验
- **离线 RL 不收敛**：先缩小动作空间（Top-200 热门物品）、调低 γ、
  加大 replay buffer；不行就退化为 REINFORCE 对照
- **手写 DQN 出 bug**：先用 CartPole 调通（10 分钟验证），再迁移到推荐环境
